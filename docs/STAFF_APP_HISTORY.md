# ATTENDANCE (Feg-tech 2.4) — Three-tab PWA

Deploy all files in this folder to an HTTPS static host (Netlify, Cloudflare Pages, or GitHub Pages). The ZIP contents must be at the web root (or same subdirectory). Open the HTTPS site on Android Chrome, then install from the browser menu.

Tabs: Register (name + face), Class (name + duration), Face Scan (camera opens automatically, matches a registered face, marks present once, and waits for Next). A class ends after the configured duration.

**Important limitations:** First run needs internet to load face-api.js and its face models from a CDN. The engine is not guaranteed to work offline. LocalStorage contains unencrypted biometric descriptors and attendance, and clearing browser storage deletes records; export backups and protect them. No anti-spoofing/liveness detection, access control, or multi-device sync. Face recognition accuracy has not been field-validated. Obtain appropriate consent for students' biometric data, especially minors, and avoid using this prototype for consequential decisions without independent verification.

Existing v2 data is retained on the same origin via the same localStorage key. Prior sessions without duration are treated as 45 minutes. Deploying to a different domain does not automatically migrate data; use Backup and Restore.

**Recognition accuracy (v5):** students are registered with 5 face samples; scanning uses full landmark alignment, quality checks (size, angle, sharpness), a margin against the second-best student, and 3 consecutive matching frames. Re-register students that show "1 sample" (type the same name and confirm replace). Adjust 'Scan strictness' in tab 2; thresholds are constants at the top of face.js.

**3D Secure mode (v6):** registration captures front, left and right head angles; scanning identifies the face straight-on, then asks for a random head turn and must match the same student from the side (also a basic photo-spoof check). Students registered before v6 show "Needs 3D re-register". 'Scan mode > Fast' keeps the old front-only scan. Not true depth sensing.

**Feg-tech 3.4: Online sync + edit everywhere.**
Setup (Firebase Realtime Database, free plan): console.firebase.google.com > create project > Build > Realtime Database > Create database. Copy its URL (looks like https://NAME-default-rtdb.firebaseio.com). In the app: 🔑 > HOD > HOD Dashboard > scroll to the last card "Online Sync & Settings" > paste the URL > Save & test. Then tap "Share link" and open that link on each lecturer and student phone once (it connects them; no typing needed).
Rules (Realtime Database > Rules): quickest is `{"rules":{".read":true,".write":true}}` (anyone who knows the URL can read/write, including stored face data). Safer: set rules to `{"rules":{".read":false,".write":false}}`, then in Project settings > Service accounts > Database secrets copy the secret and paste it in "Access key"; the shared link carries it to the other phones.
How it syncs: on app open, 2.5 s after every change, when the app returns to the foreground, on "Sync now", and every 30 s while the HOD dashboard is open. Newest change wins; deletions are synced. Student face data is uploaded, so get consent and protect the database.
Edit: Edit buttons now exist for lecturers (also "Edit my profile"), courses, students (Register list and Scan settings), classes (course name, code, level, duration), the department name (⚙️), the HOD PIN, and the sync URL/key.
